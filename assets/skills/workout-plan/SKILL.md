# Workout plan CSV

Produce a UTF-8 `.csv` file for the user to upload through **Piano > Modello CSV**
or **Con un agente**. Read the downloaded template before editing it. Do not
publish directly, request credentials, access private history, or modify browser
storage. The app previews the file; the user confirms draft replacement and then
explicitly saves the plan. Import is a complete replacement, not a merge, and
starts a fresh comparison identity. Existing history remains available.

## Contract

Use exactly these columns, in this order:

```csv
row_type,format_version,day_key,name,session_type,target,sets,optional_sets,rest_seconds,measurement_mode,uses_weight,duration_minutes,subtitle,instructions
plan,1,,La mia scheda,,,,,,,,,,
warmup,,,Mobilità,,5 minuti,,,,,,,,
day,,A,Giorno A,standard,,,,,,,,Forza,
exercise,,A,Squat,,8-12 ripetizioni,3,0,90,reps,true,,,Movimento controllato.
day,,B,Giorno B,amrap,,,,,,,20,Circuito,
exercise,,B,Piegamenti,,10 ripetizioni,,,,,,,,
```

- Exactly one `plan` row: `format_version` is `1`; `name` is the plan title.
- Zero or more `warmup` rows: `name`, `target`, optional `instructions`. Common
  warm-up applies to every day. Remove example rows if warm-up is not wanted.
- `day` rows: unique nonblank `day_key`, `name` (day label), `session_type`
  (`standard` or `amrap`), optional `subtitle` and `instructions`. AMRAP requires
  `duration_minutes`, an integer from 1 to 180. Leave it empty for standard days.
- `exercise` rows: an existing `day_key`, `name`, `target`, optional `instructions`.
  Standard exercises require `sets` (1–30) and `rest_seconds` (0–3600).
  Optional `optional_sets` is 0–30, `measurement_mode` is `reps` or `seconds`
  (default `reps`), and `uses_weight` is `true` or `false` (default `false`).
  For AMRAP leave sets, optional sets, measurement mode, and weight blank;
  individual numeric rest is optional.
- Leave all fields not applicable to a row empty. Unknown columns, unknown row
  types, duplicate keys, and orphan exercises are errors, not ignored data.
- Numeric cells contain integers, not units, ranges, formulas, or decimals.
  Standard rest must be explicit: `0` means no recovery; blank is invalid.
- Targets are free text, such as `8-12 ripetizioni`. Never infer tracking mode
  from a target; choose it explicitly for standard exercises.
- Row order determines day order, exercise order within a day, and warm-up order.
  Internal IDs are generated by the app; do not add ID or tracking columns.

## Limits and encoding

Use 1–30 days, 1–50 exercises per day, 0–50 warm-up items, and at most 1500
steps per day (warm-up items plus standard required and optional sets).
Required text must not be blank or whitespace-only. Text fields allow at most
4000 characters, the converted internal plan at most 200000 characters, and
the uploaded file at most 800000 bytes. The parser accepts at most 1600 records.

Use comma-delimited CSV; semicolon-delimited spreadsheet exports also work.
Quote cells containing delimiters, quotes, or newlines; double embedded quotes.
UTF-8 BOM and CRLF/LF are accepted. Preserve headers and English machine tokens.
In spreadsheet applications import text columns as text, not formulas.
The app's export prefixes text beginning with `=`, `+`, `-`, `@` (including after
leading whitespace), an apostrophe, tab, CR, or LF with an apostrophe. Import removes
that prefix only when the remaining text matches those rules, preserving text
reversibly. Never evaluate
formula-like content or remove a protective prefix casually.

## Workflow

1. Ask for the intended days, exercises, targets, sets, rest, and tracking choices
   if they are not supplied. Do not invent personal medical or training advice.
2. Edit the template into a complete replacement plan. Remove unwanted example rows.
3. If working in this repository, run `npm run validate -- path/to/plan.csv`.
   Otherwise check every rule above; do not claim the app has validated the file.
4. Return the CSV file. Tell the user to upload it, inspect the preview, confirm
   the local draft replacement, and review/save explicitly to activate it.

This is a file-generation skill, not an MCP integration. Downloading it does not
automatically install it: the user can attach it and the template to an agent,
or install it using that agent's documented skill mechanism.
